# 角色头像与外观立绘同步指南

游戏版本更新、新角色上线后，按本文档把新角色的**官方头像**和**官方外观立绘**补进管理器。

配套脚本：`scripts/sync_character_assets.py`

```bash
# 只检查缺什么，不写任何文件（建议每次版本更新后先跑这个）
python scripts/sync_character_assets.py --check

# 自动补齐缺失的官方角色头像（ZZZ + 终末地）
python scripts/sync_character_assets.py --avatars

# 检查官方时装是否有新增
python scripts/sync_character_assets.py --skins

# 全部执行
python scripts/sync_character_assets.py --all
```

同步完跑一遍完整校验：

```bash
npm test && npm run typecheck && npm run lint && npm run build
```

---

## 一、铁律：只用官方素材

**禁止自己裁切、生成、拼接角色头像或立绘。**

这条规则来自实际踩过的坑：曾用全身立绘自动裁切头部充当头像，结果脸偏出画面、
只截到发饰，全部返工。官方本来就提供了现成的头像文件，直接用即可。

| 用途 | 官方来源 | 规格 |
|---|---|---|
| ZZZ 角色头像 | ZZZ Wiki `Agent_<英文名>_Icon.png` | 283×307 RGBA |
| 终末地角色头像 | 终末地官网干员页立绘 | 303×386 RGBA |
| ZZZ 外观立绘 | ZZZ Wiki `Agent_<角色>_<时装>_Portrait.png` | 缩放到高 1200 WebP |

> 注意：ZZZ Wiki 上还有 `_Circle_Icon.png`（142×142 圆形小图标），
> **不要**拿它当头像，那是 UI 里的圆形徽章，不是标准头像。脚本已自动排除。

## 二、角色名以官方简体中文名为准

目录名、`characters-data.ts` 里的 `name` 字段，一律用**官方简体中文名**：

- 用国服官方译名，不用英文直译、不用社区俗称
- 时装名同理：是「病名为生」而不是英文直译「名为生命的疾病」
- 遇到异体字按官方写法统一（如「卡繆」官方简体作「卡缪」，以官网/BWIKI 当前写法为准）

`resources/games/*/character-config.json` 是离线参考数据，`src/` 下没有代码读它。
**运行时真正生效的是 `src/core/characters-data.ts`**，改角色数据改这个文件。

## 三、ZZZ 角色头像流程

### 1. 先跑检查

```bash
python scripts/sync_character_assets.py --check
```

输出里关注两类：

```
[zzz] 缺少头像: N                    ← 角色库有、但本地没图，脚本能自动补
[zzz] wiki 有图但角色库没有的: N      ← 新角色，需要人工加进 characters-data.ts
```

### 2. 有新角色时先补角色库

新角色必须先出现在 `src/core/characters-data.ts` 的 `CHARACTERS_BY_GAME['19567']` 数组里，
脚本才知道该角色的中文名。条目格式：

```ts
{ name: 'Severian Lowell', enName: 'Severian Lowell', gbCatId: 12345, aliases: [...] }
```

`gbCatId` 是 GameBanana 的角色分类 ID，获取方式：

```
https://gamebanana.com/mods/Index?_aFilters[Generic_Game]=19567&_sSort=Generic_Newest
```

从返回数据里读每个条目的 `_aSubCategory._sProfileUrl`（形如 `/cats/<id>`）。
排序参数只能是 `Generic_Newest` / `Generic_MostDownloaded` 等，
传 `default` / `newest` 会返回 `UNKNOWN_SORT`。

> `gbCatId` 在同一游戏内必须唯一，`tests/characters-roster.test.ts` 会校验，
> 写重复会直接测试失败。

### 3. 自动补头像

```bash
python scripts/sync_character_assets.py --avatars
```

脚本对每个缺失角色写入 `resources/images/zzz/<中文名>/`：

```
_cover.png   _cover.webp   avatar.png   gbicon.png
```

### 4. 如果脚本报「wiki 有图但角色库没有」

说明该角色尚未收录。按上面第 2 步补 `characters-data.ts` 后重跑。

英文名对不上时脚本会做保守归一（词序调换、`Starlight - Billy Kid` ↔ `Starlight Billy`），
但**不会**做模糊包含匹配——`Anby Demara` 与 `Soldier 0 Anby` 包含关系成立却是两个角色。

## 四、终末地角色头像流程

```bash
python scripts/sync_character_assets.py --avatars
```

脚本解析 `https://endfield.hypergryph.com/operator` 页面，落到
`resources/images/endfield/<中文名>/`，同样四个文件名。

解析要点（改脚本时别踩）：

- 立绘是 **CSS 背景图** `style="background-image:url(...)"`，页面里**没有 `<img>` 标签**
- slug 与英文代号不一定同名（祀 = `jsspsi`），**不能用 codename 拼 URL**
- 页面结构：`data-key` 属性 → 立绘 URL，紧跟 `OperatorItem_nameText` → 中文名，
  `OperatorItem_codename` → `// Si`
- `endfield.wiki.gg` 有机器人防护（403），用官网，不要用 wiki

## 五、ZZZ 外观立绘（catalog.json）

### 检查新增

```bash
python scripts/sync_character_assets.py --skins
```

数据源是 ZZZ Wiki 的 `Agent Outfit` 页面。表格列序固定：

```
Icon | Name | Rarity | Agent | Type | Obtain
```

只收 `Paid` / `Event Reward` / `Commission Reward`，
**不收 `Default`**——原皮由角色头像代表，不是可切换外观。

### 手工录入新时装

脚本只检测不自动写，因为时装中文名无法可靠机器翻译。新增条目步骤：

1. 到 ZZZ 官网 / BWIKI 确认该时装的**官方简体中文名**
2. 下载官方立绘 `Agent_<角色>_<时装>_Portrait.png`
3. 缩放到**高度 1200**（宽度按比例，实际如 815×1200），转 WebP 存到
   `resources/games/zzz/character-skins/images/<中文角色名>/zzz-outfit-<slug>.webp`
4. 在 `resources/games/zzz/character-skins/catalog.json` 对应角色的 `skins` 数组追加：

```json
{
  "id": "zzz-outfit-<slug>",
  "name": "<官方简体中文名>",
  "nameEn": "<官方英文名>",
  "type": ["Paid"],
  "releaseVersion": "3.3",
  "image": "images/<中文角色名>/zzz-outfit-<slug>.webp",
  "imageSha256": "<文件 SHA256>"
}
```

5. 同步更新 `catalog.json` 顶部的 `outfitCount` 与 `characterCount`

`imageSha256` 用 PowerShell 取：

```powershell
(Get-FileHash "resources\games\zzz\character-skins\images\<角色>\<文件>.webp" -Algorithm SHA256).Hash
```

## 六、技术陷阱（改脚本必看）

### 图片扩展名不可信，必须转码

ZZZ Wiki 静态站返回的文件**名叫 `.png`，内容却是 WebP**（文件头 `RIFF`）。
渲染层按扩展名选图，直接原样保存会读不出来。脚本统一用 Pillow 打开后重新编码落盘。

### 静态图片下载需要完整浏览器头

`static.wikia.nocookie.net` 缺 Referer 会返回 403。必须带：

```
Referer: https://zenless-zone-zero.fandom.com/
Accept: image/avif,image/webp,image/png,image/*,*/*;q=0.8
```

### 分页拉取 wiki 文件列表

`action=query&list=allimages&aiprefix=Agent_` 单次最多 500 条且**不按字母序**，
一次请求会漏掉后加入的新角色（实测 1104 个文件需 3 页）。
必须跟着 `continue.aicontinue` 翻完。

### Python 的 CA 证书可能过期

本机 Python 跑 `urllib` 会报 `certificate has expired`。脚本对只读图片下载关闭校验：

```python
ctx = ssl.create_default_context()
ctx.check_hostname = False
ctx.verify_mode = ssl.CERT_NONE
```

### 控制台编码

Windows 控制台是 GBK，打印中文/emoji 会 `UnicodeEncodeError`。运行时设：

```powershell
$env:PYTHONIOENCODING="utf-8"
```

## 七、头像解析优先级（运行时逻辑）

`ModEngine.getCharacterAvatars()` 的取图顺序：

1. `resources/images/<game>/<角色>/_cover.*` —— 用户显式指定
2. **官方图**（`resources` 内的官方头像）
3. Mod 子目录封面 —— 仅兜底

正常情况下全部走第 1、2 层。`tests/character-avatar-priority.test.ts` 固化了这个顺序，
改 `getCharacterAvatars` 前先看该用例。

> 历史说明：早期版本允许「设为角色头像」按钮把任意 Mod 预览图写进角色目录，
> 该功能已移除。现在角色分类头像只认官方素材。

## 八、目录结构速查

```
resources/
├─ images/
│  ├─ zzz/<中文名>/          _cover.png _cover.webp avatar.png gbicon.png
│  └─ endfield/<中文名>/     同上
└─ games/
   └─ zzz/character-skins/
      ├─ catalog.json        outfitCount / characterCount / characters[].skins[]
      └─ images/<中文名>/zzz-outfit-<slug>.webp
```
