## 每次发版的固定流程

1. 确认 `git status` 干净，避免把无关改动带进发版提交。
2. 跑四项检查：`npm test`、`npm run typecheck`、`npm run lint`、`npm run build`。
3. 按 SemVer 判断进位，执行 `npm version <版本> --no-git-tag-version`。
4. 提交 `chore(release): 版本号改为 x.y.z`，正文列出本版功能提交。
5. 创建并推送 `v<版本>` 标签。
6. 执行 `npm run dist` 生成 NSIS 安装包。
7. 创建 GitHub Release 并上传 `LZ-Manager-Setup-<版本>.exe`。
8. 通过 GitHub API 核对资产的 `name`、`size`、`state`。
9. 删除本地 `release/`，确认工作区仍然干净。
10. 更新本清单中的版本、资产大小、SHA256 和已完成/待办状态。
